# Architecture

Phase 06 adds a Node TypeScript proxy bound to `127.0.0.1` that owns cloud provider credentials and exposes authenticated, origin-restricted, rate-limited structured analysis. The extension's `ProviderRouter` is the single cloud-routing choke point: it enforces local-only operation, hybrid fallback, and per-site consent.

Phase 06R (AI rescue) makes the AI path reliable end to end. A model returns a bounded **settings patch** (`shared/aiFields.ts`, schema generated from the Zod settings schemas by `shared/jsonSchema.ts`), validated by `parsePlan` with one corrective retry in `background/planner.ts`. Each request is a **job** (`background/aiJobs.ts`, persisted in `chrome.storage.session`, keepalive while running) that moves through run → preview → apply → undo. Preview is an overlay inside the content script's normal settings resolution (`shared/sitePatch.ts`), so there is a single apply path for saved settings and AI plans. Providers stream (SSE from llama-server, NDJSON with pings from the proxy) to stay inside MV3's fetch limits. The AI UI lives in the **side panel** (`src/sidepanel/`), which renders the stored job. The proxy (`server/src`) has pluggable Gemini and Claude backends, a live `smoke` check, and `extension/scripts/evalPlanner.ts` scores any model against `extension/eval/cases.json`.

Phase 07 ("Clean this page") lets plans act on page blocks. The content script's snapshot (`content/domSnapshot.ts`) adds up to 60 candidate **blocks** (landmarks, dialogs, fixed/sticky overlays, clutter-hinted containers, repeated card groups) with sanitised hints, a short text preview, geometry, a `protect` kind and a `main` flag, budgeted by priority. Plans may add `elements: {hide, dim, highlight}` of block ids; `shared/elementPlan.ts` validates them in code (ids, main content, 15-item and 60%-area caps, per-item confirmation for protected blocks) and also holds the keyword fallback. Preview marks elements with a random-token attribute and Apply converts them to saved selectors (`persistentSelector`); both go through `withSiteElements` into the site rule's `hiddenSelectors`/`dimSelectors`/`highlightSelectors`, executed by the `hideElements`/`dimElements`/`highlightElements` operations, so later visits need no AI call. The side panel lists items with toggles, hover outlines (Shadow DOM) and rejections, offers a one-click **Clean this page**, and flags saved rules that no longer match.

Fixes after P07: motion operations moved to `content/motionOps.ts` (reduce motion, parallax, pause autoplay; small watchers for script animations and media), sharing `content/styleEntry.ts` with the other operation modules. The Smart palette (`content/smartPalette.ts`) is now contrast-based and keeps watching the page for added or restyled content, writing back to the theme operation's style-layer entry. "Reset page" goes through `resetSiteRule` in `shared/sitePatch.ts`, which keeps the site enabled.

Phase 08 (comprehension) adds TL;DR, glossary, Explain simply, Define and Translate. The content script extracts main-content prose (`content/pageText.ts`, code blocks skipped, inline code marked); the background masks code, links and identifiers (`shared/textMask.ts`), chunks at sentence boundaries (`shared/chunk.ts`) and runs validated model calls (`background/comprehensionModel.ts`, Zod reply schemas in `shared/comprehension.ts` with JSON Schema generated by `zodToJsonSchema`) or Sarvam through the proxy's new `/v1/translate` (`server/src/providers/sarvam.ts`, reached only via `ProviderRouter.translate`). `background/comprehension.ts` checks replies, unmasks, caches (`shared/comprehensionCache.ts`) and writes per-tab state for the side panel's "Understand this page" section; the page shows results in Shadow DOM UI (`content/summaryCard.ts`, `content/selectionPopover.ts`) and glossary underlines via the CSS Custom Highlight API (`content/glossary.ts`, the `glossaryHighlights` operation). Page text is never modified.

Phase 09 (accessibility inspector) adds an "Inspect" side-panel section. The content script (`content/inspector.ts`, thresholds in `content/inspectorRules.ts`) measures the page in idle-time chunks: small text, contrast (with alpha and nested backgrounds via `content/contrast.ts`; gradients as low-confidence), tight line height, line length, walls of text, heading outline, sideways scrolling, clipped text, overlapped text, sticky/fixed bars, links that look like text and missing focus indicators. Findings (`shared/inspector.ts`) carry severity, confidence, measured evidence, a snapshot id for the Shadow DOM outline, and a fix that is a settings patch and/or element hide. `background/inspect.ts` scores them (pure `readabilityScore`), stores per-tab state in session storage, optionally asks the routed model to prioritise the numbers (`background/structured.ts` validation), and applies chosen fixes as one AI job through `applyJob`/`undoJob`, then re-checks. Three new appearance operations (`content/readabilityOps.ts`: underline links, focus outline, fix low-contrast text) give those fixes a registry path.
