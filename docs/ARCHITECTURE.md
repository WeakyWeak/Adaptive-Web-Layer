# Architecture

Phase 06 adds a Node TypeScript proxy bound to `127.0.0.1` that owns cloud provider credentials and exposes authenticated, origin-restricted, rate-limited structured analysis. The extension's `ProviderRouter` is the single cloud-routing choke point: it enforces local-only operation, hybrid fallback, and per-site consent.

Phase 06R (AI rescue) makes the AI path reliable end to end. A model returns a bounded **settings patch** (`shared/aiFields.ts`, schema generated from the Zod settings schemas by `shared/jsonSchema.ts`), validated by `parsePlan` with one corrective retry in `background/planner.ts`. Each request is a **job** (`background/aiJobs.ts`, persisted in `chrome.storage.session`, keepalive while running) that moves through run → preview → apply → undo. Preview is an overlay inside the content script's normal settings resolution (`shared/sitePatch.ts`), so there is a single apply path for saved settings and AI plans. Providers stream (SSE from llama-server, NDJSON with pings from the proxy) to stay inside MV3's fetch limits. The AI UI lives in the **side panel** (`src/sidepanel/`), which renders the stored job. The proxy (`server/src`) has pluggable Gemini and Claude backends, a live `smoke` check, and `extension/scripts/evalPlanner.ts` scores any model against `extension/eval/cases.json`.

Phase 07 ("Clean this page") lets plans act on page blocks. The content script's snapshot (`content/domSnapshot.ts`) adds up to 60 candidate **blocks** (landmarks, dialogs, fixed/sticky overlays, clutter-hinted containers, repeated card groups) with sanitised hints, a short text preview, geometry, a `protect` kind and a `main` flag, budgeted by priority. Plans may add `elements: {hide, dim, highlight}` of block ids; `shared/elementPlan.ts` validates them in code (ids, main content, 15-item and 60%-area caps, per-item confirmation for protected blocks) and also holds the keyword fallback. Preview marks elements with a random-token attribute and Apply converts them to saved selectors (`persistentSelector`); both go through `withSiteElements` into the site rule's `hiddenSelectors`/`dimSelectors`/`highlightSelectors`, executed by the `hideElements`/`dimElements`/`highlightElements` operations, so later visits need no AI call. The side panel lists items with toggles, hover outlines (Shadow DOM) and rejections, offers a one-click **Clean this page**, and flags saved rules that no longer match.

Fixes after P07: motion operations moved to `content/motionOps.ts` (reduce motion, parallax, pause autoplay; small watchers for script animations and media), sharing `content/styleEntry.ts` with the other operation modules. The Smart palette (`content/smartPalette.ts`) is now contrast-based and keeps watching the page for added or restyled content, writing back to the theme operation's style-layer entry. "Reset page" goes through `resetSiteRule` in `shared/sitePatch.ts`, which keeps the site enabled.

Phase 08 (comprehension) adds TL;DR, glossary, Explain simply, Define and Translate. The content script extracts main-content prose (`content/pageText.ts`, code blocks skipped, inline code marked); the background masks code, links and identifiers (`shared/textMask.ts`), chunks at sentence boundaries (`shared/chunk.ts`) and runs validated model calls (`background/comprehensionModel.ts`, Zod reply schemas in `shared/comprehension.ts` with JSON Schema generated by `zodToJsonSchema`) or Sarvam through the proxy's new `/v1/translate` (`server/src/providers/sarvam.ts`, reached only via `ProviderRouter.translate`). `background/comprehension.ts` checks replies, unmasks, caches (`shared/comprehensionCache.ts`) and writes per-tab state for the side panel's "Understand this page" section; the page shows results in Shadow DOM UI (`content/summaryCard.ts`, `content/selectionPopover.ts`) and glossary underlines via the CSS Custom Highlight API (`content/glossary.ts`, the `glossaryHighlights` operation). Page text is never modified.

Phase 09 (accessibility inspector) adds an "Inspect" side-panel section. The content script (`content/inspector.ts`, thresholds in `content/inspectorRules.ts`) measures the page in idle-time chunks: small text, contrast (with alpha and nested backgrounds via `content/contrast.ts`; gradients as low-confidence), tight line height, line length, walls of text, heading outline, sideways scrolling, clipped text, overlapped text, sticky/fixed bars, links that look like text and missing focus indicators. Findings (`shared/inspector.ts`) carry severity, confidence, measured evidence, a snapshot id for the Shadow DOM outline, and a fix that is a settings patch and/or element hide. `background/inspect.ts` scores them (pure `readabilityScore`), stores per-tab state in session storage, optionally asks the routed model to prioritise the numbers (`background/structured.ts` validation), and applies chosen fixes as one AI job through `applyJob`/`undoJob`, then re-checks. Three new appearance operations (`content/readabilityOps.ts`: underline links, focus outline, fix low-contrast text) give those fixes a registry path.

Phase 10 (supervised fix) changes what hybrid means: the local model drafts, code measures, the cloud reviews, the user decides. `background/aiJobs.ts` runs every AI request as draft → measure → review → final on the job record (`shared/aiJob.ts` `supervision`: stepper, ledger, scores, review status). Measuring is the content script's `MEASURE_PAGE` (`content/measure.ts`: inspector findings, visible main text, text hidden on purpose, visible protected elements); `background/supervise.ts` previews states, measures them and undoes changes that regress (`shared/review.ts` `regressions`), decides whether to review (mode, consent, review policy), takes Set-of-Mark screenshots (`background/screenshot.ts`, activeTab), calls `ProviderRouter.review` (review model with fallback; never in local mode) with prompts from `background/reviewPrompt.ts`, maps missed screenshot regions to blocks, and folds the reply in with `applyReview` (same validators as a plan). The snapshot (`content/domSnapshot.ts`) now segments the page so blocks no longer depend on class-name keywords, and supports drill-down (`EXPAND_BLOCKS`, used by the planner's `expand`). The side panel's `SupervisionView` shows the stepper, scores before → draft → final, each item as kept / removed / added / undone with its reason and source, and the screenshots the reviewer saw; Explain simply adds a code fidelity check and an opt-in cloud meaning check. The proxy has a third backend, OpenAI-compatible (`server/src/providers/openai.ts`).


P10 fixes (after live testing on real sites) made code the safety net rather than the models. `content/domUtils.ts` has the one main-content finder (`findContentRegion`: the element holding most of the page's prose, with a selector unique to it), used by typography, measurements, the snapshot, focus ops and the element picker. Snapshot blocks carry `textShare` and `title`, and the validator never hides or dims a block holding the page title or ≥ 35% of its prose. `supervise.ts` `guardSettings` applies code rules to both the draft and the reviewer's settings before measuring: a fix run keeps only settings a measured problem calls for (`FIX_FIELDS`), and width changes must help (`guardWidth`). The reviewer now really receives its screenshots, and a refused review is retried with a simpler schema. Screenshots on every site come from an optional `<all_urls>` permission requested by a button (`sidepanel/ScreenshotAccess.tsx`).

Phase 11 (dyslexia first) measures what helps each reader instead of presuming. New registry ops in `content/dyslexiaOps.ts`: `noItalics`, `unjustify`, `noAllCaps` (marker ops over computed styles, helpers in `content/markers.ts`) and `backgroundTint` (white surfaces → cream/peach/yellow/soft grey, text kept ≥ 7:1 via `contrast.ts` `readableTextOn`); spacing is now em with research presets, OpenDyslexic and Arial join the fonts, and profiles carry `dyslexiaLens`, `aids` (for P12) and a `note`. The reading-fit test (`shared/fitPassages.ts`, pure tournament in `shared/fitTest.ts`, UI in `src/fit/`, shown in the side panel's "Reading support" and Options) renders each passage in `fitreader/index.html`, an extension page that applies the same applier and ops, times reading, asks one question and saves the winner as a profile; nothing leaves the browser. The dyslexia lens adds six finding types to the inspector (`content/inspector.ts`, thresholds in `inspectorRules.ts`, syllables from TeX hyphenation patterns in `shared/syllables.ts`) and a "dyslexia" score category; the score card reads "Score for you". The dyslexia reading view (`background/readingView.ts`, overlay `content/readingView.ts`) reuses the P10 roles on text: local draft, code fidelity check, cloud review with page-text consent, preview over an unchanged page. "Describe how reading feels" (`describeMe`, `background/describeModel.ts`, `describeMe.ts`, `shared/describe.ts`) turns a description into a checked, previewed starting profile and points to the fit test to confirm it.

Evidence behind P11 (never overclaimed in the UI): Wallace et al. 2022 (ACM TOCHI): the same reader read up to 35% faster in their best font than their worst, with comprehension unchanged, and the best font differs per person, hence the fit test. Zorzi et al. 2012 (PNAS): extra letter spacing improved reading speed and accuracy in dyslexic children. Rello & Baeza-Yates: larger text and character spacing help readers with and without dyslexia; italics read slowest; sans-serif, upright and monospaced fonts read better. Rello & Bigham 2017: warm backgrounds (peach, orange, yellow) beat white, blue-grey was slowest. British Dyslexia Association style guide: left-aligned text, no ALL CAPS body text, about 1.5 line spacing, off-white backgrounds. No reliable benefit has been shown for OpenDyslexic, Dyslexie or Bionic-style bolding: OpenDyslexic is only a fit-test candidate. The fit test is not a diagnosis, and short tests are noisy.

P11 follow-up: a "Plain reading view" (`content/plainReader.ts`) shows the main content exactly as written in the same overlay as the dyslexia reading view (`content/readingView.ts` now takes generic reader content), with no AI and no summary. Links have their own named colour (`linkColor`, a second instance of the colour operation factory in `content/readabilityOps.ts`), and the planner fills in settings a request names outright when the local model leaves them out (`addNamedSettings`).
