# Decisions

- 2026-10-19 (P06): Verified Google’s Gemini REST `generateContent` guidance: use `v1beta/models/{model}:generateContent`, `generationConfig.responseMimeType` plus `responseSchema` for structured JSON, and `parts[].inlineData` for inline images; default cloud model is the configurable `gemini-3.8-flash`.
- 2026-10-19 (P06): Cloud provider keys remain only in `server/.env`; the extension stores only the user-created token that authorizes the local proxy.
- 2026-10-19 (P06): Hybrid sends text planning to local AI first and falls back to cloud only after a local failure and explicit consent; visual analysis always requires cloud consent.
- 2026-10-19 (P06 follow-up): Resolve the proxy environment file relative to the proxy source so `server/.env` is loaded consistently by workspace scripts and direct Node starts.
- 2026-10-20 (P06 follow-up): Use Gemini 3.8's documented `generationConfig.responseFormat.text` structured-output shape and cap cloud responses at 4,096 tokens.
- 2026-10-20 (P06 follow-up): Cloud requests have a two-minute limit in both the extension and local proxy; saved 30-second cloud timeouts migrate automatically on extension reload.
- 2026-10-20 (P06 follow-up): The MV3 background worker registers the same operation definitions as the content script because each runs in an isolated JavaScript context.
- 2026-10-22 (P06R): Models return a flat, bounded settings patch (`changes`) over a curated subset of the settings schemas (`shared/aiFields.ts`) instead of a list of `{opId, params}`. Small local models fill it far more reliably, and it cannot express hiding navigation, selectors or CSS. The Operation registry still executes it through the normal resolver, so there is one apply path.
- 2026-10-22 (P06R): The plan's JSON Schema is generated from the Zod settings schemas, then adapted per provider dialect (llama.cpp keeps bounds; Claude drops min/max/length keywords; Gemini OpenAPI fallback drops additionalProperties). Zod validation of every reply stays authoritative.
- 2026-10-22 (P06R): Preview is an in-memory overlay on the site's rule inside the content script (`withSitePatch`), resolved by the same applier as saved settings, so DOM mutations re-apply it instead of erasing it. Apply saves the identical patch; Undo restores the exact previous site rule captured at Apply time.
- 2026-10-22 (P06R): AI work runs as a per-tab job persisted in `chrome.storage.session`; the side panel renders the stored job, so closing/reopening the panel or a worker restart never loses a result. A 20 s `getPlatformInfo` keepalive runs while a job is active.
- 2026-10-22 (P06R): Local replies stream over SSE and the proxy streams NDJSON with 5 s pings, so the service worker receives bytes well inside Chrome's 30 s fetch-response limit.
- 2026-10-22 (P06R): The AI UI moved to Chrome's Side Panel (stays open while the page is used); the popup keeps quick settings and an "Open AI assistant" button.
- 2026-10-22 (P06R): Hybrid never falls back to cloud after a user cancel; without consent it returns `consent-required` carrying the local error so the user can choose; a denied site returns `consent-denied` (no dialog loop); allow-once is consumed only when cloud was actually used.
- 2026-10-22 (P06R): Cloud backends are pluggable behind the proxy: Gemini (`generateContent` with `responseMimeType` + `responseJsonSchema`, auto-retrying with `responseSchema` if rejected; verify with `npm run smoke`) and Claude via `@anthropic-ai/sdk` with `output_config.format` json_schema, effort `low` by default, and the server-side refusal fallback (`fallbacks: "default"`) on models that support it. Default Claude model `claude-opus-5-5`.
- 2026-10-22 (P06R): Proxy CORS accepts any `chrome-extension://` origin unless `ALLOWED_ORIGIN` pins ids (comma list); web origins are always rejected and the bearer token is the real authorisation. This removes the "wrong extension id → 403" failure.
- 2026-10-22 (P06R): Demo mode and AI failures use keyword rules (`shared/intents.ts`) to propose a bounded patch with no model.
- 2026-10-22 (P06R): `targetRef` (element-targeted plan steps) is dropped for now; P07/P08 can add element-scoped fields when a concrete operation needs them.
- 2026-10-22 (P06R): Local timeout default raised to 120 s (migration v9) because replies now stream; manifest host permissions now cover `127.0.0.1:*` as well as `localhost:*`.
- 2026-10-22 (P06R eval): Real runs. Local Qwen2.5-Coder-7B Q4_K_M on an RTX 4050 6 GB (`-ngl 99 -c 8192`): 25/25 eval cases, 100% valid plans, p50 1.7 s, p95 6.8 s, no injection failures. Gemini through the proxy: `responseJsonSchema` accepted by the live API; `gemini-3.8-flash`, `gemini-3.7-flash` and `gemini-flash-latest` returned 503 "high demand"; `gemini-3.5-flash-lite` answered correctly (4/5 sampled cases, one Google-side timeout), so it is the new default.
- 2026-10-22 (P06R eval): Small models restyle colours on vague requests ("set up for studying"). Prompting alone did not fix it, so the planner drops theme/contrast/brightness/saturation changes unless the request mentions colour or light, and tells the user it did.
- 2026-10-22 (P06R): The Gemini proxy retries 503/504 twice (1.5 s, 4 s) with a 35 s per-attempt cap, so the proxy always reports "Gemini is busy" before the extension's 120 s limit.
- 2026-10-23 (P07): Element plans name snapshot ids only (`elements: {hide, dim, highlight}`), never selectors. The schema offers them as an enum of the snapshot's block ids; `validateElements` (code) rejects unknown ids, the main content and its ancestors, more than 15 hides and more than 60% of the page area, and lists every rejection with a reason.
- 2026-10-23 (P07): `elements` is a required property (lists may be empty) whenever the page has blocks. llama.cpp's JSON-schema grammar emits optional properties after all required ones, so with it optional the local model never produced element lists (recall 0.00 → 1.00 after the change).
- 2026-10-23 (P07): Protected blocks (contain navigation, a form or an alert, or are a dialog with focusable controls) are listed but start disabled; ticking one in the side panel is the per-item confirmation. Only hides need it; dim/highlight are not destructive. Cookie banners and newsletter pop-ups usually count as protected.
- 2026-10-23 (P07): Fixed/sticky overlays don't count toward the 60% area cap (they cover the page rather than being part of it; a full-screen newsletter backdrop alone measured 46%). A hide inside another hidden block is folded into "Not applied" so the user is not asked to confirm it twice.
- 2026-10-23 (P07): Element changes are dropped unless the request is about page parts (hide/remove/clean/clutter/banner/highlight/dim…), mirroring the colour guard; page text cannot turn "make the text bigger" into a hide.
- 2026-10-23 (P07): Preview marks live elements with `data-awl-preview="<random token>-<id>"` and feeds `[data-awl-preview=…]` selectors through the same `withSiteElements` + focus operations that Apply uses with saved selectors. Snapshot ids are reused only when this script assigned them, so a page cannot copy ids onto other elements.
- 2026-10-23 (P07): Apply converts ids with `persistentSelector`: `robustSelector` (id, test ids, aria-label, unique classes), else a short child path from the nearest robust ancestor or body. Items that cannot be converted are reported, not silently dropped. Saved lists start from the resolved value so profile selectors are kept; each list is capped at 30.
- 2026-10-23 (P07): Hovering an item outlines it from a closed Shadow DOM overlay; hovering a hidden item temporarily un-hides it ("peek") so it can be seen.
- 2026-10-23 (P07): Demo mode and the AI-failure fallback use keyword clean-up (`suggestElements`): only the clutter kinds the request names (all but comments for a generic clean-up), never kinds named after "keep"/"except", never navigation, the ToC or the main content.
- 2026-10-23 (P07): Per-item reasons are not requested from the model (id arrays keep replies short for small models); items show the block's label, and the plan's reasons appear under "Why".
- 2026-10-23 (P07 eval): Local Qwen2.5-Coder-7B Q4_K_M, real run: 33/33 cases (25 settings + 8 element), element precision 1.00 and recall 1.00 over 5 scored cases, no injection failures, p50 1.9 s, p95 7.2 s. Live check on clutter.html in local mode: one model call; reload re-applied all four hides with zero model calls; Undo restored them.
- 2026-10-23 (P07): Added jsdom (dev dependency) for DOM unit tests (snapshot blocks, ids → selectors round trip); jsdom has no layout, so tests stub element boxes.
- 2026-10-23 (fix): "Reset page" no longer turns the extension off for the site. It replaces the site rule with one that is enabled, drops the site's own changes, and pins to default anything the global settings or a profile would still change there (`resetSiteRule`), so the page looks untouched and the next change applies at once. It also clears an AI preview on the page. Sites an old reset turned off come back on when reset again.
- 2026-10-23 (fix): The popup's Reading panel now saves per site (like Appearance and Focus), so Reset page can undo text changes too. Text settings for every site come from a profile (popup Profile menu, profiles edited in Settings).
- 2026-10-23 (fix): Reduce motion makes CSS animations and transitions run once and end immediately (`.01ms`, one iteration) instead of `animation: none`, so content that fades in or waits for animationend/transitionend still appears; animations started from script (Web Animations API) are finished, or paused if endless, every 500 ms while it is on.
- 2026-10-23 (fix): Reduce parallax is plain CSS (`background-attachment: scroll` everywhere, `transform: none` on parallax-named/data-attribute elements), so it covers content added later; the over-broad `[class*=scroll]` match is gone.
- 2026-10-23 (fix): Pause autoplay pauses any playback that the user did not ask for, not just `[autoplay]` media: a press within 1 s anywhere, or within 8 s on or near the player, counts as the user's, and media they started is never paused again (even when other settings re-apply). The autoplay attribute is cleared on media added later and restored when the setting is turned off.
- 2026-10-23 (fix): Smart theme picks text colour by contrast (WCAG 4.5:1) against the background the text actually sits on after recolouring, keeps the site's colour when it is already readable or nothing does better, and leaves text over a covering background image or gradient as designed. It recolours content added or restyled later (debounced MutationObserver; class changes re-read small subtrees only), keeping unchanged rules byte-identical so scrolling does not rewrite the stylesheet.
- 2026-10-23 (fix): `fixtures/motion-autoplay.html` now has a playable WebM clip (generated with ffmpeg, 46 KB) and a script-started video; the old empty data: source could never play. New `fixtures/smart-header.html` covers brand-colour, gradient, sticky and late-added headers.
- 2026-10-23 (fix): Popup panels each kept their own copy of the settings from when the popup opened and saved the whole copy back, so a Focus toggle after choosing Smart Dark restored the old (empty) appearance and the active profile's theme (Study: sepia) showed. All popup writes now go through `useSettings` → `patchSettings` (read latest, change one group via `withSiteRule`, save), and panels follow `onSettingsChange`. The Settings page also follows changes made elsewhere.
- 2026-10-23 (P08): Comprehension jobs are a second job scope next to page plans (`beginJob(tabId, "understand")`), so a TL;DR never cancels a running plan; their per-tab state (`awl_understand_<tabId>` in session storage) holds the last TL;DR, glossary and selection result for the side panel.
- 2026-10-23 (P08): Masking uses numbered placeholders `[[n]]` for code (marked by the extractor), URLs, emails and identifiers (camel/snake/SCREAMING case, dotted names, calls, `--flags`). Text that already looks like a placeholder is masked too, so it round-trips unchanged; Devanagari digits in placeholders are accepted. Live check: Sarvam kept `[[1]]` intact.
- 2026-10-23 (P08): Sarvam Translate verified in docs.sarvam.ai (Translate Text, 2026-10-23) and live with `npm run smoke`: `POST https://api.sarvam.ai/translate`, `api-subscription-key`, `sarvam-translate:v1`, ≤ 2000 characters. The proxy's `/v1/translate` returns plain JSON (one short chunk per call); the extension chunks at sentence boundaries.
- 2026-10-23 (P08): Translation is cloud-only in the router (`ProviderRouter.translate`): unreachable in local mode, consent-gated in hybrid/cloud, no silent fallback. The local model is offered explicitly as "lower quality".
- 2026-10-23 (P08): Reading time is counted (220 words/minute), not taken from the model; key terms and glossary terms must occur in the page text; summary sentences that add links or emails the page lacks are dropped (the usual shape of an injected instruction).
- 2026-10-23 (P08): Long pages: the TL;DR summarises up to 3 context-sized chunks and merges them (the card says how much it covered); the glossary uses the first chunk only.
- 2026-10-23 (P08): The TL;DR card is the first child of the main content (not a sibling, so Collapse sidebars cannot hide it); the selection UI is a small "✨ Understand" button first, so selecting text to copy is not interrupted; it can be turned off in Settings → AI. Glossary underlines use the CSS Custom Highlight API through a `glossaryHighlights` operation, so no page text is wrapped or changed.
- 2026-10-23 (P08): Results are cached per kind + hash(URL without fragment, variant, text) for 24 h, newest 40 kept; Clear all data wipes them. Demo mode returns clearly labelled extracts (first sentences, pattern-picked terms) and does not translate.
- 2026-10-23 (P08 eval): Local Qwen2.5-Coder-7B Q4_K_M, `npm run eval:comprehension`: 6/6 (TL;DR 5.0 s, glossary 10.7 s, explain simply 2.0 s, define 1.2 s, local translation 5.2 s, injection summary clean). Live in Chromium (hybrid, local first): TL;DR 4.5 s, 12 glossary terms / 19 underlines, cached TL;DR 0.1 s, Sarvam translation 3.8 s with URL and identifiers restored, page text unchanged.
- 2026-10-23 (P08): Root `npm test` and `npm run typecheck` now include the server (`node --test`, type stripping).
- 2026-10-23 (fix): The selection popover's host is zero-sized, so the panel shrank to its narrowest content ("skinny"). It is now a pill toolbar (actions) and a fixed-width card (min(400px, viewport − 24px)) with a header (title, close), body (result; original folded under "Original text") and footer (source, Copy); placed below the selection, or above when there is no room.
- 2026-10-23 (fix): Clean this page hides every copy of a clutter widget: a hidden block whose class names a clear clutter kind (ad, sponsor, promo, banner, newsletter, cookie, related, recommend, share, social, popup, modal, overlay, paywall) is previewed and saved as `tag.class` when that matches 2–40 elements, none of them the main content, navigation or a form. Copies loaded later (while scrolling) are covered by the same CSS rule. The snapshot lists one block per kind ("+ N more like it") and scans class/id hints over the whole page (25,000 elements), not only the first 4,000.
- 2026-10-23 (fix): Clearing a preview removes every marker carrying this page's token, including copies a page cloned from a marked element.
- 2026-10-23 (fix): The glossary panel explains the feature, shows how often each term is underlined on the page (reported back by the content script), and "Show" scrolls to the first one and opens its definition. Terms in the text but split by formatting say "not underlined".
- 2026-10-23 (P09): Inspector checks run in the content script on the page as currently shown (settings applied), so re-checking after a fix measures its effect. Budget: at most 4,000 elements read in 300-element idle-callback chunks; all style/box reads happen before any write. The report says how many elements were scanned and whether the cap was hit.
- 2026-10-23 (P09): Readability score = 100 − Σ per category of min(cap, Σ severity × confidence); severity high 10 / medium 5 / low 2, confidence high ×1 / medium ×0.6 / low ×0.25; caps contrast 25, text size 15, dense text 15, line length 10, headings 10, layout 15, links & focus 10 (sum 100). Monotonic and order-independent by construction (unit-tested); the panel shows the three largest category penalties.
- 2026-10-23 (P09): Contrast composites translucent text and backgrounds up the tree (`content/contrast.ts`, now shared with the Smart palette). Text over a gradient is judged against every colour stop and reported with low confidence and no automatic fix; text over url() images is not judged. Code (`pre`, `code`) is not checked.
- 2026-10-23 (P09): Three new appearance settings (and AI fields) so every fix is a settings patch: `underlineLinks`, `focusRing`, `fixContrast` (marks failing text with a per-page token and gives it #111/#f8f8f8, or a link blue that passes; watches added content; off when Smart colours already handle contrast). Other fixes reuse existing fields: fontSize 18, lineHeight 1.6, maxContentWidth 720, staticifyStickyHeaders, or an element hide (P07 format) for a fixed bar with no navigation/form/alert/dialog inside. Headings, overflow, clipping and overlap get advice only.
- 2026-10-23 (P09): Applying fixes writes one AI job (`source: "inspector"`) and calls the existing `applyJob`, so the fix is saved to the site rule, survives reload and is undone by the same `undoJob`; the inspector then re-checks and shows the score before → after. Applying a fix replaces a preview in the AI section on the same tab.
- 2026-10-23 (P09): Keyboard focus is checked by focusing up to 8 links/buttons (`focus({preventScroll, focusVisible})`) and comparing styles; samples where the browser does not apply `:focus-visible` to script focus are skipped, and if none count, readable stylesheets are scanned for `:focus { outline: none }` rules with no replacement (medium confidence). Focus is restored afterwards.
- 2026-10-23 (P09): "Explain with AI" sends only ids, types, severities, confidences and measured numbers (no labels, element ids or page text) through the router; replies are Zod-validated (`runValidated`, now shared with comprehension) and priorities naming no real finding are dropped. Demo mode ranks findings by score cost, labelled. Local Qwen2.5-Coder-7B: valid explanation of the 18 findings on a11y-issues.html in 6.7 s.
- 2026-10-24 (P10): Hybrid now means "local drafts, code measures, cloud reviews" (was: cloud only when local fails). Every AI run (typed request, Clean this page, Fix this page) is supervised: the draft is previewed and measured; any change that lowers the readability score, removes main text not hidden on purpose, hides over 25% of the main text, adds sideways scrolling/overlap/clipping, or makes navigation/forms/alerts disappear is undone automatically (cloud additions first, then one change at a time, ≤ 6 re-measurements). Code has the last word over both models.
- 2026-10-24 (P10): The cloud reviewer returns `{verdict, drop[{ref, reason}], add{changes, elements}, missedRegions[], notes}` (every field required; refs and ids are enums of the draft and the snapshot). Additions go through the plan's own checks (field bounds, colour rule, element validator), so the reviewer cannot hide main content or skip protection. Unknown refs are reported, never applied.
- 2026-10-24 (P10): Review policy setting `always` (default) / `first-per-site` / `when-unsure` (confidence < 0.6, no score gain, or > 30% of element items refused). Default is `always` (not first-per-site as the phase file suggested) because supervision is the product's point and runs only on user actions. Without consent the result is shown as "not reviewed" with a consent card and "Review with cloud AI"; a failed review keeps the measured draft.
- 2026-10-24 (P10): Separate `reviewModel` (default `gemini-3.5-flash`, verified with structured output and image input by `npm run smoke`); on timeout/overload/rate limit the router reviews with `cloudModel` (`gemini-3.5-flash-lite`). The free-tier quota of 3.5-flash ran out after ~10 calls during the eval, so the fallback matters. `gemini-3.8-flash` timed out on the smoke test.
- 2026-10-24 (P10): Candidate blocks come from page segmentation instead of keyword gates: the page's parts (looking through single-child wrappers), siblings along the path to the main content, and boxes inside the article (prose excluded), plus the old landmarks/overlays/hints as rank boosts. Blocks report `children`, `inMain` and measured `ad` signals (cross-site frames, ad hosts, ad-slot markup; never on a wrapper of the main content). Form controls are never blocks.
- 2026-10-24 (P10): Drill-down: the planner may answer `expand: [ids]` (≤ 3 per round, ≤ 2 rounds) for blocks with ≥ 2 parts, only on requests about page parts; the content script returns their parts as new blocks and the model is asked again.
- 2026-10-24 (P10): Screenshots: visible viewport only, downscaled to ≤ 1280 px, numbered Set-of-Mark boxes drawn on an OffscreenCanvas copy (red = what the draft changes, blue = other blocks), never on the page; ≥ 600 ms between captures (Chrome allows 2/s). The reviewer can name a missed area in % of the screenshot; `elementsFromPoint` maps it to the smallest block covering ≥ 60% of it (≤ 4× its size), which then goes through the validator.
- 2026-10-24 (P10): captureVisibleTab needs `<all_urls>` or `activeTab` (site host permissions are not enough, verified). The manifest is unchanged (no `<all_urls>`): screenshots work after the user opens the extension from its toolbar button on that tab or presses the new Alt+Shift+F "Fix this page" shortcut (both grant activeTab); otherwise the review runs on text and measurements and says so.
- 2026-10-24 (P10): Page text reaches the reviewer only with a separate per-site opt-in (`privacy.cloudTextSites`, a checkbox on the consent card, off by default, withdrawn by "Deny"). Explain simply now runs a code fidelity check (numbers, dates, amounts, names, negations) on every rewrite and, with that opt-in, a cloud meaning check; findings appear as "Check the original: …" notes.
- 2026-10-24 (P10): "Fix this page" (button and Alt+Shift+F) sends the local model the measured problems (types and numbers only) and adds the inspector's high-confidence settings fixes the draft left out (ledger source "inspector").
- 2026-10-24 (P10): The proxy gained an OpenAI-compatible backend (`OPENAI_COMPAT_BASE_URL`/`_API_KEY`/`_MODEL`; json_schema, one retry in JSON mode) so any compatible provider can be the reviewer; the Anthropic backend stays (needs a funded API key; a Claude Pro subscription does not include API access).
- 2026-10-24 (P10): The Minions-style long-page path (cloud style brief → local per chunk → cloud reviews a sample) is implemented as `chunksToReview` (every flagged chunk + 3 evenly spaced); it gets its first multi-chunk user in P11's dyslexia reading view, since Explain simply works on one selection.
- 2026-10-24 (P10): Supervisor eval (`npm run eval:supervisor`, 12 drafts with planted mistakes + 6 rewrites, text only): gemini-3.5-flash-lite caught 10/10 then 9/10 planted mistakes on two runs with 1 false alarm each, approved 2/3 good drafts, p50 1.4 s, ~1,400 input tokens per review, meaning check 4/4 with 0/2 false alarms; gemini-3.5-flash 4/4 before its quota ran out; the local Qwen2.5-Coder-7B as its own reviewer caught 4/10 with 25 false alarms (meaning check 4/4). - 2026-10-24 (P10): Planner eval with segmented snapshots and the new rules: local Qwen 34/35 (valid plans 100%, element precision 1.00, recall 0.93; missed the "Recommended" rail once), both obfuscated-page cases pass, no injection failures.
- 2026-10-24 (P10 fixes): One main-content finder for the whole extension (`findContentRegion` in content/domUtils.ts; the copies in domSnapshot, focusOps and the element picker are gone): a `<main>` holding the prose, else the `<article>` holding it, else the smallest element with ≥ 60% of the page's prose (paragraph-like text, mostly-link items excluded), else the largest article, else the whole page.
