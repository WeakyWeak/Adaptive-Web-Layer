# Decisions

- 2026-10-19 (P06): Verified Google’s Gemini REST `generateContent` guidance: use `v1beta/models/{model}:generateContent`, `generationConfig.responseMimeType` plus `responseSchema` for structured JSON, and `parts[].inlineData` for inline images; default cloud model is the configurable `gemini-3.8-flash`.
- 2026-10-19 (P06): Cloud provider keys remain only in `server/.env`; the extension stores only the user-created token that authorizes the local proxy.
- 2026-10-19 (P06): Hybrid sends text planning to local AI first and falls back to cloud only after a local failure and explicit consent; visual analysis always requires cloud consent.
- 2026-10-19 (P06 follow-up): Resolve the proxy environment file relative to the proxy source so `server/.env` is loaded consistently by workspace scripts and direct Node starts.
- 2026-10-20 (P06 follow-up): Use Gemini 3.8's documented `generationConfig.responseFormat.text` structured-output shape and cap cloud responses at 4,096 tokens.
- 2026-10-20 (P06 follow-up): Cloud requests have a two-minute limit in both the extension and local proxy; saved 30-second cloud timeouts migrate automatically on extension reload.
- 2026-10-20 (P06 follow-up): The MV3 background worker registers the same operation definitions as the content script because each runs in an isolated JavaScript context.
- 2026-10-22 (P06R): Models return a flat, bounded settings patch (`changes`) over a curated subset of the settings schemas (`shared/aiFields.ts`) instead of a list of `{opId, params}`. Small local models fill it far more reliably, and it cannot express hiding navigation, selectors or CSS. The Operation registry still executes it through the normal resolver, so there is one apply path.
- 2026-10-22 (P06R): The plan's JSON Schema is generated from the Zod settings schemas, then adapted per provider dialect (llama.cpp keeps bounds; Claude drops min/max/length keywords; Gemini OpenAPI fallback drops additionalProperties). Zod validation of every reply stays authoritative.
- 2026-10-22 (P06R): Preview is an in-memory overlay on the site's rule inside the content script (`withSitePatch`), resolved by the same applier as saved settings, so DOM mutations re-apply it instead of erasing it. Apply saves the identical patch; Undo restores the exact previous site rule captured at Apply time.
- 2026-10-22 (P06R): AI work runs as a per-tab job persisted in `chrome.storage.session`; the side panel renders the stored job, so closing/reopening the panel or a worker restart never loses a result. A 20 s `getPlatformInfo` keepalive runs while a job is active.
- 2026-10-22 (P06R): Local replies stream over SSE and the proxy streams NDJSON with 5 s pings, so the service worker receives bytes well inside Chrome's 30 s fetch-response limit.
- 2026-10-22 (P06R): The AI UI moved to Chrome's Side Panel (stays open while the page is used); the popup keeps quick settings and an "Open AI assistant" button.
- 2026-10-22 (P06R): Hybrid never falls back to cloud after a user cancel; without consent it returns `consent-required` carrying the local error so the user can choose; a denied site returns `consent-denied` (no dialog loop); allow-once is consumed only when cloud was actually used.
- 2026-10-22 (P06R): Cloud backends are pluggable behind the proxy: Gemini (`generateContent` with `responseMimeType` + `responseJsonSchema`, auto-retrying with `responseSchema` if rejected; verify with `npm run smoke`) and Claude via `@anthropic-ai/sdk` with `output_config.format` json_schema, effort `low` by default, and the server-side refusal fallback (`fallbacks: "default"`) on models that support it. Default Claude model `claude-opus-5-5`.
- 2026-10-22 (P06R): Proxy CORS accepts any `chrome-extension://` origin unless `ALLOWED_ORIGIN` pins ids (comma list); web origins are always rejected and the bearer token is the real authorisation. This removes the "wrong extension id → 403" failure.
- 2026-10-22 (P06R): Demo mode and AI failures use keyword rules (`shared/intents.ts`) to propose a bounded patch with no model.
- 2026-10-22 (P06R): `targetRef` (element-targeted plan steps) is dropped for now; P07/P08 can add element-scoped fields when a concrete operation needs them.
- 2026-10-22 (P06R): Local timeout default raised to 120 s (migration v9) because replies now stream; manifest host permissions now cover `127.0.0.1:*` as well as `localhost:*`.
- 2026-10-22 (P06R eval): Real runs. Local Qwen2.5-Coder-7B Q4_K_M on an RTX 4050 6 GB (`-ngl 99 -c 8192`): 25/25 eval cases, 100% valid plans, p50 1.7 s, p95 6.8 s, no injection failures. Gemini through the proxy: `responseJsonSchema` accepted by the live API; `gemini-3.8-flash`, `gemini-3.7-flash` and `gemini-flash-latest` returned 503 "high demand"; `gemini-3.5-flash-lite` answered correctly (4/5 sampled cases, one Google-side timeout), so it is the new default.
- 2026-10-22 (P06R eval): Small models restyle colours on vague requests ("set up for studying"). Prompting alone did not fix it, so the planner drops theme/contrast/brightness/saturation changes unless the request mentions colour or light, and tells the user it did.
- 2026-10-22 (P06R): The Gemini proxy retries 503/504 twice (1.5 s, 4 s) with a 35 s per-attempt cap, so the proxy always reports "Gemini is busy" before the extension's 120 s limit.
- 2026-10-23 (P07): Element plans name snapshot ids only (`elements: {hide, dim, highlight}`), never selectors. The schema offers them as an enum of the snapshot's block ids; `validateElements` (code) rejects unknown ids, the main content and its ancestors, more than 15 hides and more than 60% of the page area, and lists every rejection with a reason.
- 2026-10-23 (P07): `elements` is a required property (lists may be empty) whenever the page has blocks. llama.cpp's JSON-schema grammar emits optional properties after all required ones, so with it optional the local model never produced element lists (recall 0.00 → 1.00 after the change).
- 2026-10-23 (P07): Protected blocks (contain navigation, a form or an alert, or are a dialog with focusable controls) are listed but start disabled; ticking one in the side panel is the per-item confirmation. Only hides need it; dim/highlight are not destructive. Cookie banners and newsletter pop-ups usually count as protected.
- 2026-10-23 (P07): Fixed/sticky overlays don't count toward the 60% area cap (they cover the page rather than being part of it; a full-screen newsletter backdrop alone measured 46%). A hide inside another hidden block is folded into "Not applied" so the user is not asked to confirm it twice.
- 2026-10-23 (P07): Element changes are dropped unless the request is about page parts (hide/remove/clean/clutter/banner/highlight/dim…), mirroring the colour guard; page text cannot turn "make the text bigger" into a hide.
- 2026-10-23 (P07): Preview marks live elements with `data-awl-preview="<random token>-<id>"` and feeds `[data-awl-preview=…]` selectors through the same `withSiteElements` + focus operations that Apply uses with saved selectors. Snapshot ids are reused only when this script assigned them, so a page cannot copy ids onto other elements.
- 2026-10-23 (P07): Apply converts ids with `persistentSelector`: `robustSelector` (id, test ids, aria-label, unique classes), else a short child path from the nearest robust ancestor or body. Items that cannot be converted are reported, not silently dropped. Saved lists start from the resolved value so profile selectors are kept; each list is capped at 30.
- 2026-10-23 (P07): Hovering an item outlines it from a closed Shadow DOM overlay; hovering a hidden item temporarily un-hides it ("peek") so it can be seen.
- 2026-10-23 (P07): Demo mode and the AI-failure fallback use keyword clean-up (`suggestElements`): only the clutter kinds the request names (all but comments for a generic clean-up), never kinds named after "keep"/"except", never navigation, the ToC or the main content.
- 2026-10-23 (P07): Per-item reasons are not requested from the model (id arrays keep replies short for small models); items show the block's label, and the plan's reasons appear under "Why".
- 2026-10-23 (P07 eval): Local Qwen2.5-Coder-7B Q4_K_M, real run: 33/33 cases (25 settings + 8 element), element precision 1.00 and recall 1.00 over 5 scored cases, no injection failures, p50 1.9 s, p95 7.2 s. Live check on clutter.html in local mode: one model call; reload re-applied all four hides with zero model calls; Undo restored them.
- 2026-10-23 (P07): Added jsdom (dev dependency) for DOM unit tests (snapshot blocks, ids → selectors round trip); jsdom has no layout, so tests stub element boxes.
- 2026-10-23 (fix): "Reset page" no longer turns the extension off for the site. It replaces the site rule with one that is enabled, drops the site's own changes, and pins to default anything the global settings or a profile would still change there (`resetSiteRule`), so the page looks untouched and the next change applies at once. It also clears an AI preview on the page. Sites an old reset turned off come back on when reset again.
- 2026-10-23 (fix): The popup's Reading panel now saves per site (like Appearance and Focus), so Reset page can undo text changes too. Text settings for every site come from a profile (popup Profile menu, profiles edited in Settings).
- 2026-10-23 (fix): Reduce motion makes CSS animations and transitions run once and end immediately (`.01ms`, one iteration) instead of `animation: none`, so content that fades in or waits for animationend/transitionend still appears; animations started from script (Web Animations API) are finished, or paused if endless, every 500 ms while it is on.
- 2026-10-23 (fix): Reduce parallax is plain CSS (`background-attachment: scroll` everywhere, `transform: none` on parallax-named/data-attribute elements), so it covers content added later; the over-broad `[class*=scroll]` match is gone.
- 2026-10-23 (fix): Pause autoplay pauses any playback that the user did not ask for, not just `[autoplay]` media: a press within 1 s anywhere, or within 8 s on or near the player, counts as the user's, and media they started is never paused again (even when other settings re-apply). The autoplay attribute is cleared on media added later and restored when the setting is turned off.
- 2026-10-23 (fix): Smart theme picks text colour by contrast (WCAG 4.5:1) against the background the text actually sits on after recolouring, keeps the site's colour when it is already readable or nothing does better, and leaves text over a covering background image or gradient as designed. It recolours content added or restyled later (debounced MutationObserver; class changes re-read small subtrees only), keeping unchanged rules byte-identical so scrolling does not rewrite the stylesheet.
- 2026-10-23 (fix): `fixtures/motion-autoplay.html` now has a playable WebM clip (generated with ffmpeg, 46 KB) and a script-started video; the old empty data: source could never play. New `fixtures/smart-header.html` covers brand-colour, gradient, sticky and late-added headers.
- 2026-10-23 (fix): Popup panels each kept their own copy of the settings from when the popup opened and saved the whole copy back, so a Focus toggle after choosing Smart Dark restored the old (empty) appearance and the active profile's theme (Study: sepia) showed. All popup writes now go through `useSettings` → `patchSettings` (read latest, change one group via `withSiteRule`, save), and panels follow `onSettingsChange`. The Settings page also follows changes made elsewhere.
